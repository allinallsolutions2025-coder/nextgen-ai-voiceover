## Scope

Audit baseline: `main` at `3be5fef81f766043d002adec6a0270f6b5068873` (November 5, 2026).

The review covered the browser app entry point, PWA/service-worker files, core speech and audio modules, preview generation/loading, automated tests, GitHub Actions workflows, desktop and Android packaging configuration, and GitHub Pages documentation.

The audit preserved the English-first Kokoro browser workflow and the 28 American/British English voices.

## Findings and changes

### Fixed in this audit branch

1. **Malformed PWA metadata in `index.html`.** Two literal backslash-`n` sequences were present in the document head around the manifest link and mobile metadata. They were converted into actual line breaks so the browser can parse the tags. The build checker now requires the manifest link to be a standalone head element.
2. **Preview cache smoke-test version mismatch.** The application opens IndexedDB schema version 2 and writes preview records tagged with sample version 2. The live Pages test explicitly opened database version 1 and filtered for sample version 1, which would raise an IndexedDB `VersionError` or report zero saved previews. The test now opens the current database version and validates record versions against `database.version`.
3. **Unpinned Playwright installation.** The live Pages and offline browser-test workflows installed the floating latest Playwright package. The previous live Pages run failed during npm installation because its `playwright-core@1.65.0` dependency was not available at that time, before Chromium or the app test started. Both browser-test workflows now pin Playwright to `1.65.0`.
4. **Stale GitHub Pages guide.** The guide still described the older manual-only deployment process and an outdated build payload. It now documents the current automatic Pages workflow, published artifact boundaries, browser smoke test, offline model test, and manual verification steps.
5. **Stale dependency lockfile.** At the audit baseline, `package.json` was version `0.2.0`, while `package-lock.json` still declared `0.1.0` and contained no dependency entries. The Pages workflow staged the lockfile regenerated by `npm install` together with the voice-preview assets. The resulting lockfile was committed on `main` as `d0b1a2ad1b2f4b6c205bc7ab9d8e5b64f7e301dc`; it declares version `0.2.0` and includes the resolved dependency graph. PR #11 was then merged as `bd8046ae1ee26221a23fee6ca8e7e9ac00be66de`: all five build/test workflows and the README now use `npm ci`. Node 24 CI and the post-merge deployment, offline, desktop and Android workflows passed with that committed lockfile.

## Extended hardening in the follow-up review

The follow-up review added these changes on a branch based on the latest `main`:

- **Preview asset integrity:** require the manifest to contain exactly the app's 28 supported English voices; reject duplicate or unknown voice IDs, mismatched filenames, invalid byte counts and malformed SHA-256 digests. Before a bundled preview is cached or marked ready, verify its RIFF/WAVE signature, exact byte length and SHA-256 checksum. If a bundled WAV fails validation, it is shown as unavailable and remains eligible for local model-based regeneration.
- **Preview-integrity regression tests:** cover valid manifests, wrong model revisions, incomplete or duplicate voice lists, unknown voice IDs, path-like filenames, malformed metadata, WAV framing, file-length mismatches, checksum mismatches and unavailable Web Crypto.
- **Smoke-test stability:** let the generation smoke helper accept an already-completed status as well as an intermediate status, avoiding a timeout when short scripts finish between Playwright polls.
- **Legacy API security:** the separate FastAPI backend now rejects requests with HTTP 503 when `NEXTGEN_API_KEY` is not configured and compares supplied keys with `hmac.compare_digest`. The backend README now documents the required Hugging Face Space secret. The helper has tests for missing, wrong, matching and non-ASCII keys.
- **CI wiring:** include the new JavaScript module in syntax checks and build guards, include the new Python helper in byte-compilation checks, and run the additional JavaScript/Python unit tests through the existing test suites.

The follow-up PR #12 head commit `b9b917ce89e22ffc5cd84dcaacc3cedd581c1f47` passed GitHub Actions CI run [#167](https://github.com/allinallsolutions2025-coder/nextgen-ai-voiceover/actions/runs/43447546181). The run completed syntax checks, all **65 Node.js tests** (including checksum/size/WAV-header validation of all 28 committed production WAV previews), the static Vite build and deployment-output checks, Python byte-compilation and all **8 Python tests**. The new checksum validation code has not yet been exercised by the deployed live-site Chromium workflow; that still needs to run after PR #12 is merged and Pages is redeployed.
